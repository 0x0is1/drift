# MEMORY — decision log + live status

Plain project doc, not Claude Code's internal memory system. Append here as decisions/status change. Read before planning any new phase.

## Origin

Rewrite of `lissen-mobile` (JioSaavn-backed music player, Expo/RN). Old app's custom StyleSheet UI got hard to maintain ("lost the track, skills issue" — user's words). Original vision was a drag-up/down player ↔ album-songlist transition that never got built right. This rewrite exists to get that interaction right with Tamagui instead of hand-rolled styles, plus grow the app into algo-feed + social-sync-listening territory.

## Decisions (locked 2026-10-11)

- **Repo**: new sibling folder `D:\codes\lissen-v2`, not in-place rewrite of `lissen-mobile`. Old repo stays as reference/fallback until cutover.
- **Language**: full TypeScript rewrite (old app had a stray untracked `tsconfig.json` and a deleted `jsconfig.json` — already drifting this direction before this conversation).
- **Path aliases**: hardcore, see `CLAUDE.md` tsconfig section. User explicitly asked for this mid-planning.
- **Scope for this build pass**: everything in one shot — UI rewrite + Tamagui + Supabase backend + DB schema + algo feed + sync-listen sessions all targeted now, not deferred to a later milestone. Only auth *UI* is deferred (schema/anon-id is not).
- **Nav**: Expo Router (file-based), replacing `@react-navigation/*`. Route names/behavior carry over, library doesn't.
- **Backend/DB**: Supabase. Chosen for realtime (sync sessions) + auth (later phase) + Postgres (algo training queries) in one managed service.
- **Auth**: Supabase Auth, email+password + Google/Apple OAuth — but that's the *later* phase. Right now: anonymous Supabase auth from first launch so every table has a stable `user_id` from day one.
- **Sync-listen sessions**: queue+transport-state sync only (Realtime broadcast of play/pause/seek/track-change + shared queue). Explicitly not sample-accurate audio sync — that's a much bigger project, descoped on purpose.
- **Feed tab algo v1**: heuristic/rules over a Postgres event log (plays/skips/likes, language/artist/genre overlap, recency). No ML model yet. Event logging must run from day one even though the heuristic is simple, because that log is the training data for a real model later.
- **Colors/theme**: port `lissen-mobile/src/constants/colors.js` 1:1 into Tamagui tokens first, no new palette invented.
- **app.json/eas.json**: reused with same `extra.eas.projectId` (`edf2085f-2a08-4fbe-990f-e33ee757f0d6`) and package `com.lissenmobile` — this rewrite ships as an update to the *same* app, not a new store listing.
- **Commits**: title-only, no co-author line, no description body, caveman-terse.
